# Lesson 100：调试——程序员最重要的技能（常备技能 · 一）

> 写代码只占 30% 时间，**调试**占 70%。这一课教你调试的方法论，
> 学会它，你就不再怕报错，反而能从中快速进步。

---

## 1. 心态：报错是你的朋友

- 报错**不是失败**，是程序在告诉你「哪里有问题」
- 越是厉害的工程师，越会**认真读报错**——报错信息里藏着答案
- 记住：**你写的每一行代码，电脑都会严格检查**；报错只是它没看懂你的意思

## 2. 报错信息怎么看（三步法）

```
Traceback (most recent call last):
  File "D:\...\hello.py", line 5, in <module>    ← 第 2 步：看文件名和行号
    print(name)                                   ← 出错的那行代码
NameError: name 'name' is not defined             ← 第 1 步：看最后一行！错误类型+说明
```

1. **先看最后一行**：错误类型 + 一句话说明（最关键）
2. **再看中间**：哪个文件哪一行出的错
3. **最后看那行代码**：结合上下文找原因

**常见错误类型速查**：

| 类型 | 意思 | 常见原因 |
|------|------|----------|
| `SyntaxError` | 语法错误 | 少冒号、引号没配对、f-string 引号冲突 |
| `NameError` | 名字未定义 | 变量拼写错、没定义就用 |
| `TypeError` | 类型不对 | 字符串和数字混着 `+` |
| `IndexError` | 下标越界 | 列表只有 3 个元素却取 `[5]` |
| `KeyError` | 键不存在 | 字典取了一个没有的键 |
| `ValueError` | 值不对 | `int("abc")` 之类转换失败 |

## 3. 调试三板斧

### 第一斧：print 大法（90% 的情况够用）

在关键位置打印变量值，看程序走到哪、值是什么：

```python
for i in range(10):
    print(f"循环第 {i} 次")   # 看它跑了多少次、i 是多少
    # ...其他代码
```

```python
x = "123"
print(type(x))   # 打印类型，确认是不是字符串——类型错是万恶之源
```

### 第二斧：分段注释

把代码一段一段注释掉（`#` 开头），先跑通一半，再加回来——定位是哪段出的问题。

### 第三斧：最小复现

把报错的代码**简化到最小**，单独跑一个文件。
问题越简单越好找，而且简化过程本身常常就让你发现了原因。

## 4. 给 AI 报 bug 的正确姿势（很重要！）

**坏例子**：`它报错了，帮我看看`

**好例子**：
```
代码（贴上来）：
...
我运行后报错（贴完整报错）：
Traceback ...
我预期是：打印出列表长度
实际是：报错了
我已经检查过：变量名没拼错
```

- **信息越全，AI 帮得越快、越准**
- 这一步本身就在锻炼「精确描述问题」的能力——面试和工作中的核心软技能
- 求助前先自己用三板斧试 5 分钟

## 5. 练习

把 lesson-004 的猜数字程序**故意改错 3 处**（比如把 `==` 写成 `=`、下标错一位、漏个冒号），
然后用三板斧逐个找到并修好。**会制造错误、会修错误，才算真会。**
